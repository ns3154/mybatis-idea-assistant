# ADR-0002：统一语义模型与增量索引

- 状态：已接受
- 日期：2026-08-11
- 决策范围：S2 XML 符号、Mapper、配置、TypeAlias、模块作用域与缓存失效
- 关联文档：`docs/S2-统一语义模型与增量索引任务卡.md`、`docs/S2-统一语义模型与增量索引验收记录.md`

## 1. 背景

B01～B04 的 `namespace#statementId` 索引足以支撑首条导航和 Inspection 纵切面，但无法稳定承载 `resultMap`、SQL fragment、配置、TypeAlias、继承 Mapper、Kotlin K2 和多模块语义。继续在导航或检查中增加专用扫描会产生多套事实源、作用域串联和失效不一致。

S2 需要一个只读、可取消、可增量失效的统一底座，同时保持首批的精确匹配原则：没有充分证据就不认定，不用文件名、简单类名或目录距离补猜测。

## 2. 决策

### 2.1 统一 XML 符号键

XML 索引键由符号类型、完整 namespace 和可选 id 组成：

```text
namespace: TYPE + NUL + namespace
具名符号: TYPE + NUL + namespace + NUL + id
```

`TYPE` 明确区分 namespace、statement、resultMap 和 SQL fragment。NUL 分隔符不得出现在输入段中。重复键只在单文件内去重；跨文件候选全部保留。

新的索引 ID 为 `mybatis.idea.assistant.xml.symbol`。这会自然废弃 B02 的旧单用途索引缓存，不沿用旧索引版本号或数据格式。

### 2.2 索引器只做安全线性扫描

- DataIndexer 只读取 `FileContent`，不创建 PSI、不解析 Java 类型、不访问项目服务；
- 使用 NanoXML 风格的安全包装，禁止内部/外部实体解析；
- 只接受 `mapper` 直接子元素和无前缀的精确标签/属性名；
- 不完整、无关或结构不支持的 XML 对当前文件返回空，不污染其他文件；
- 扫描和结果循环显式检查取消，平台取消异常向上传播。

MyBatis 原生配置和 Spring Boot/MyBatis-Plus properties/YAML 使用独立索引 ID，因为输入格式、值模型和失效边界不同；上层配置模型负责确定性合并。

### 2.3 Mapper 是带证据的类型化模型

接口只有在出现以下至少一种精确证据时才认定为 Mapper：

- XML namespace 与接口全限定名完全相等；
- 精确 `@Mapper` 注解；
- 满足 `@MapperScan`/`@MapperScans` 的包和过滤条件；
- MyBatis XML 配置显式注册类或包。

模型包含声明来源、可见继承方法、泛型替换后的参数和返回类型、实体形状、`@Param`、SQL/Provider/Flush 注解来源。普通接口、不可解析过滤器和不支持的源返回类型化状态，不扩大扫描范围。

Kotlin 通过平台提供的 Java light class 建模；核心生产路径不直接依赖 Kotlin API。Kotlin 插件仍是运行时可选依赖，测试沙箱显式装载它以验证 K2 行为。

### 2.4 配置和 TypeAlias 使用同一上下文作用域

配置模型合并 MyBatis XML 与 Boot/MyBatis-Plus 的配置位置、Mapper 位置、Mapper 类/包、TypeAlias 包和 TypeHandler 包。Boot 配置支持 properties、YAML、列表、标量、profile 与宽松命名；包含未解析占位符或不支持结构的值保持保守。

TypeAlias 支持内置别名、显式/默认别名、包扫描和 `@Alias`。冲突目标全部保留。包解析通过平台类名索引建立按上下文缓存的类目录，不遍历项目文件系统，也不在索引器中嵌套查询 Stub Index。

### 2.5 模块可见性先于项目全局性

所有用户上下文查询必须使用调用元素的 resolve scope；XML 反向查询使用 XML 所在模块及其依赖和库的作用域。MapperScan 证据也记录来源文件并校验调用模块可见性。

项目级重载仅用于无调用上下文的兼容入口和专用测试；编辑器导航、Inspection 与模型解析不得默认扩大到 `projectScope`。

### 2.6 缓存按真实语义依赖失效

缓存依赖包括 Mapper 及继承声明源文件的修改戳、XML/配置索引修改戳、MapperScan 语义指纹、项目根和 Dumb 状态。广义索引脏信号触发重算后，如果语义快照不变，可以复用旧模型对象；无关 Java/XML 编辑不应让所有 Mapper 永久失效。

`IndexNotReady`、`SourceInvalid` 和项目关闭结果不缓存。取消异常永远不转换成普通空结果。

## 3. 被否决的方案

### 3.1 为每类功能保留独立 statement 扫描

会让导航、Inspection、引用和补全拥有不同事实源，重复解析 XML，并在修改期间产生不一致结果。

### 3.2 在索引器中创建 PSI 或解析 Java 类型

违反 FileBasedIndex 的索引约束，容易造成递归索引访问、Dumb Mode 异常和不可控性能。

### 3.3 按简单类名、文件名或最近目录识别 Mapper

多模块和同名接口下会制造错认。S2 宁可返回 `NotMapper` 或 `IndexNotReady`，也不提升猜测命中率。

### 3.4 所有查询使用 projectScope

会把不可见模块的同名 Mapper、XML、配置和别名混入当前结果，破坏 Java 项目依赖语义。

### 3.5 用永久 Map、TTL 或全局 PSI 修改计数缓存

永久 Map 无法安全处理 PSI 生命周期，TTL 不对应语义变化，全局修改计数又会让任意编辑驱逐全项目结果。S2 改用平台 CachedValue 与具体修改依赖。

## 4. 结果与代价

正面结果：

- S3～S7 可以复用同一个 XML、Mapper、配置和 TypeAlias 事实源；
- 未保存编辑、多模块和 Dumb Mode 行为可测试、可解释；
- 10 万 statement 的真实索引查询与 141 个平台测试建立了当前规模基线；
- Kotlin、Spring、YAML、Database 可选依赖关闭时核心插件仍能加载。

需要接受的代价：

- 索引 ID 变化会触发一次重建；
- TypeAlias 包解析首次需要枚举平台类名索引，随后按上下文缓存；
- Kotlin K2 依赖 light class 行为，IDE 平台升级时必须复跑兼容测试；
- S2 只提供模型与查询，不直接交付完整引用、补全、重构或写入能力。

## 5. 验证方式

必须同时通过：

1. 两套 Maven 语料；
2. Gradle 平台测试、Checkstyle、覆盖率、项目配置和插件结构；
3. 最低 IDEA 2026.1 GA Plugin Verifier；
4. 10 万 statement 真实索引查询、多模块根变化和未保存编辑测试；
5. 20/20 沙箱生命周期与 5/5 可选依赖隔离；
6. 副屏真实 IDEA 多模块语料导入且本插件错误为 0。

## 6. 重新评审触发条件

- XML 键不再由符号类型、完整 namespace 和 id 精确组成；
- 引入需要 I/O、网络或数据库访问的索引器；
- 默认查询作用域扩大为全项目；
- TypeAlias 或 Mapper 识别引入文件名、简单类名等启发式规则；
- 缓存开始长期持有 PSI，或取消/Dumb Mode 不再类型化降级；
- S3～S7 发现统一模型无法表达合法 MyBatis 语义，需要改变公共结果类型。
