# ADR-0001：独立实现与首批架构

- 状态：已接受
- 日期：2026-08-09
- 决策范围：B01 Mapper 方法到 XML statement 的最小纵切面，以及 B02/B03 精确解析增量
- 关联文档：`交付阶段实施规划.md`、`docs/首批任务卡.md`、`docs/功能矩阵.md`

> 2026-08-09 补充：B01、B02、B03 均已实现，并通过统一质量门与对应真实 IDE 验收。

## 1. 背景

项目目标是开发可公开发布、可长期维护的 MyBatis IntelliJ IDEA 插件。首批需要尽快证明 Java Mapper、Mapper XML、索引、解析和导航能够形成真实闭环，同时避免在语义核心尚未稳定时引入动态 SQL、数据库、生成器或多框架适配的复杂度。

同类开源或商业产品可以帮助理解用户场景，但不能成为来源不明的代码、资源、名称和交互复制入口。项目还需要在 IntelliJ PSI 生命周期、Dumb Mode、线程模型和增量索引约束下保持正确。

## 2. 决策

### 2.1 独立实现边界

本项目采用可审计的独立实现方式：

1. 行为依据来自 MyBatis 官方公开规范、IntelliJ Platform 官方公开文档、自行编写的样例与测试；
2. 不反编译、不抓取、不复制商业插件的二进制、源码、资源、名称、文案或界面布局；
3. 开源项目只作为公开资料参考。若需要复制或改写任何代码，必须先确认许可证兼容性，并记录来源版本、许可证、修改范围和署名要求；
4. B01 默认不复制任何第三方插件实现代码，只使用 Maven/Gradle 正式依赖；
5. 每次评审都要能回答“这段行为和实现依据是什么”，来源不清时停止合入。

这是一项工程与发布约束，不代表对第三方产品行为做兼容承诺。

### 2.2 先单工程、后按证据拆模块

B01 使用一个 IntelliJ 插件 Gradle 工程，暂不为每个逻辑层创建独立 Gradle 子模块。源码从第一天按逻辑包隔离，建议使用以下后缀；根包名由仓库构建配置统一确定：

| 逻辑包 | 职责 | 不得承担的职责 |
|---|---|---|
| `model` | 不可变稳定键、解析结果和值对象 | 不依赖编辑器 UI，不持有长期 PSI |
| `java` | 从 Java PSI 提取 Mapper 与方法描述 | 不查询 XML 文件，不做导航 |
| `xml` | 从 XML PSI 提取 namespace、statement 与文本位置 | 不识别 Java Mapper |
| `index` | 保存和查询可序列化的 Mapper/statement 索引数据 | 不保存 `PsiElement`，不做 UI |
| `resolve` | 组合 Java 描述与 XML 索引，产出唯一、缺失、多候选等结果 | 不直接弹窗，不静默消歧 |
| `navigation` | 把解析结果接入 IDE 导航入口 | 不重新扫描项目或另建匹配规则 |
| `inspection` | 后续消费解析结果提供问题提示 | B01 不提供写文件 Quick Fix |
| `platform` | 线程、取消、Dumb Mode、兼容适配和项目生命周期封装 | 不放业务匹配规则 |

只有出现明确的独立发布、依赖隔离、构建性能或可选插件类加载需求时，才把逻辑包提升为 Gradle 子模块。拆分必须另写 ADR，避免初期模块数量大于可验证功能数量。

### 2.3 单向依赖

首批依赖方向固定为：

```text
navigation ──> resolve ──> index ──> model
                    ├────> java ───> model
                    └────> xml ────> model

platform 为线程与生命周期适配层，可被上层使用，但不得反向依赖 navigation。
```

`navigation` 只能消费 `resolve` 的结果，不能自行按文件名或简单类名补一套匹配逻辑。这样后续检查、补全和反向导航可以共享同一个解析事实源。

### 2.4 首批稳定键与匹配规则

首批只接受精确键：

```text
MapperKey    = Java 接口全限定名
XmlMapperKey = mapper/@namespace 完整值

MethodKey    = MapperKey + "#" + Java 方法名
StatementKey = XmlMapperKey + "#" + statement/@id
```

`MapperKey == XmlMapperKey` 且 `MethodKey == StatementKey` 时才形成匹配。

明确不采用以下启发式规则：

- XML 文件名等于接口简单类名；
- namespace 的末段等于接口简单类名；
- statement `id` 与方法名大小写近似；
- 在项目中搜索第一个同名文本；
- 根据目录距离或索引返回顺序选择候选。

多候选是合法的解析结果，交给上层展示；不能被转换成“唯一匹配”。正向 Java → XML 遇到 Java 重载时返回“不支持的源”并保持静默，避免把任一重载伪装成参数级唯一匹配；反向 XML → Java 则保留全部同名重载，由平台展示候选。

### 2.5 索引和 PSI 生命周期

XML 关联查询使用 IntelliJ 增量索引能力，不在导航或编辑器高亮路径中遍历项目文件。

- 索引值只保存字符串、文件标识和可序列化位置数据；
- 索引或缓存中不长期持有 `PsiElement`；
- 获得候选文件后，在合法 ReadAction 内重新解析当前 PSI；
- 跨异步边界只传稳定键或 `SmartPsiElementPointer`；
- 项目关闭、任务取消、PSI 失效时结束当前查询；
- Dumb Mode 返回结构化的“索引未就绪”结果，不把异常暴露给用户，也不回退到全项目扫描。

B02 在现有 statement 键之外增加 namespace marker：只要 `mapper/@namespace` 合法，即使文件中没有任何 statement，也要记录该 namespace 的存在性。marker 与 statement 键写入同一个 `FileBasedIndex`，索引版本从 1 升级到 2，强制旧缓存重建。解析层由此可以在不扫描项目的前提下区分“无 Mapper XML”和“statement 缺失”。

具体选用 `FileBasedIndex`、Stub Index 或 DOM 扩展点，以目标 SDK 的实际 API 和平台测试为准；若改变上述数据与生命周期约束，不需要因为技术类名不同而重写本 ADR。

### 2.6 失败语料隔离

`samples/java-mybatis-minimal` 同时承担两类职责：

- `src/main` 是能由 MyBatis 实际加载和执行的正常项目；
- `src/test/.../fixtures` 与 `src/test/resources/corpus/failures` 是插件解析测试的失败输入。

生产 `mybatis-config.xml` 只加载正常 Mapper XML。失败语料不参与运行时 SqlSessionFactory 初始化，但其 Java 接口仍由 Maven 测试编译，其 XML 仍由契约测试校验，从而避免为了“构建通过”把失败用例变成无效文本文件。

### 2.7 B02 类型化解析结果

B02 用稳定结果类型替代空集合与异常文本的混合约定：

- 唯一匹配；
- 无 Mapper XML；
- statement 缺失；
- 多候选；
- 索引未就绪；
- 源已失效；
- 不支持的源。

导航层只能按结果类型决定直达、展示候选或安全降级，不得重新检查文件名或拼接另一套匹配规则。多候选目标用智能指针跨越 UI 展示边界；平台取消异常继续向上传播，不得被转换为普通“无结果”。

### 2.8 B03 XML 到 Java 的反向导航

B03 的反向键仍遵守 B01 的精确语义：

```text
mapper/@namespace 完整值 ──精确 FQN──> Java 接口
statement/@id          ──精确方法名──> 当前接口声明的方法候选
```

- 只处理 `mapper` 直接子元素中 `select`、`insert`、`update`、`delete` 的 `id`；
- 只接受 namespace 与 Java 接口全限定名完全相等，不使用简单类名、XML 文件名或目录推断；
- 一个同名 Java 方法时直达；存在重载时保留全部同名方法，由平台展示候选；
- 不把继承方法、参数签名推断、框架基类或 Kotlin 接口纳入 B03；
- Dumb Mode、无精确接口、源失效和不支持的 XML 结构均安全降级。

### 2.9 兼容与真实样例质量门

- 每次提交/PR 执行 `./gradlew check verifyPluginProjectConfiguration verifyPluginStructure verifyPlugin`；
- 同一门禁执行 `mvn --batch-mode --file samples/java-mybatis-minimal/pom.xml clean verify`；
- Plugin Verifier 的最低基线使用 IntelliJ IDEA 2026.1 GA；
- 定时或手动任务增加 IntelliJ IDEA 2026.2，用于提前发现下一版本兼容问题。

2026.1 GA 是最低发布兼容证据，2026.2 是前瞻信号；后者失败需要登记风险，但是否阻断当前发布由单独发布决策确定。

## 3. 被否决的方案

### 3.1 一开始拆成大量 Gradle 子模块

否决原因：首批只有一条纵切面，过早拆分会增加插件描述符、测试夹具、依赖和发布配置成本，尚无独立构建收益。

### 3.2 导航时扫描所有 XML

否决原因：实现简单但无法满足大型项目性能、Dumb Mode 和可取消要求，也会让后续补全与检查重复扫描。

### 3.3 用文件名和简单类名提高匹配率

否决原因：会在多模块、同名 Mapper 和重构场景中产生可信度更低的错跳。首批宁可明确无结果，也不返回错误目标。

### 3.4 直接复用其他插件实现

否决原因：会引入许可证、来源、版本耦合和独立实现风险，也无法保证其线程与索引模型符合本项目目标。

## 4. 结果与代价

正面结果：

- 首批目标足够窄，可以用真实样例和平台测试形成端到端证据；
- 导航、未来检查和补全共享同一解析事实源；
- 精确键优先降低错跳和误报；
- 类型化结果可被正向导航、反向导航与后续 Inspection 复用；
- 失败语料与可运行样例同时保留；
- 独立实现和第三方来源边界可以在公开仓库中审计。

需要接受的代价：

- B01 对非标准 namespace、继承 Mapper、Java 重载和多模块配置支持有限；
- Dumb Mode 期间功能可能暂不可用；
- 采用增量索引比直接扫描需要更多平台测试；
- 索引版本升级会触发一次缓存重建；
- Java 重载在 B03 中会出现候选列表，而不是伪装成参数级唯一匹配；
- 单 Gradle 模块需要依靠包边界和架构测试防止层间渗透。

## 5. 验证方式

自动化验证：

```bash
./gradlew check verifyPluginProjectConfiguration verifyPluginStructure verifyPlugin
mvn --batch-mode --file samples/java-mybatis-minimal/pom.xml clean verify
```

CI 对 2026.1 GA 执行上述阻断门；定时或手动任务另验 2026.2。B02/B03 还需分别覆盖类型化结果、namespace marker、精确 FQN、Java 重载候选与 Dumb Mode。

真实 IDE 验证：

1. 打开正常样例，从 `UserMapper.findById` 跳到唯一 XML statement；
2. 验证 namespace 不匹配与 statement 缺失均不产生错误跳转；
3. 修改、撤销、移动 XML 后确认索引结果同步变化；
4. 验证索引期间不抛未捕获异常、不触发全项目扫描；
5. 检查重复键时展示候选，不静默选第一个。

2026-08-09 已在副屏幕 IDEA 2026.1.4 沙箱完成 B01 的真实 gutter、唯一目标、多候选、改名失效和撤销恢复验收；XML 移动由平台测试覆盖。同日完成 B03 XML → Java 唯一目标直达与 `long/String` 重载候选弹窗验收；B02/B03 的 38 个平台测试及 2026.1 GA Plugin Verifier 均通过。

## 6. 重新评审触发条件

出现以下情况时必须补充或替代本 ADR：

- 引入 Kotlin、Spring、Database Tools 等可选插件依赖；
- 逻辑包需要拆成独立 Gradle 模块；
- stable key 不再是全限定名与 statement `id`；
- namespace marker 不再与 statement 键共享索引生命周期；
- 增加跨模块、多 XML、继承或重载的消歧规则；
- 引入或改写第三方插件源码；
- 索引实现需要长期保存 PSI 或回退到全项目扫描。
