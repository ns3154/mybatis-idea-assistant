# ADR-0012：四版本兼容与最低 SDK

## 状态

已接受，2026-08-12。覆盖 ADR-0001 中“最低 2026.1 GA”的兼容基线，不改变其独立实现、索引和保守语义决策。

## 背景

S13 要求最近四个稳定 IntelliJ IDEA 大版本通过 Plugin Verifier 和真实 IDE 冒烟。截至 2026-08-12，四个版本是 2025.2、2025.3、2026.1、2026.2。原工程以 2026.1.4 SDK 编译并声明 `since-build=261`，即使高版本二进制验证通过，也无法证明 2025.2/2025.3 可加载。

JetBrains 官方兼容指南要求多版本插件优先针对最低受支持版本编译。只把描述符改成较低 `since-build` 会允许旧 IDE 安装包含新 API 调用的二进制，属于不可接受的假兼容。

## 决策

1. 最低编译 SDK 固定为 IntelliJ IDEA Ultimate 2025.2.6.2，`since-build=252`，Java 21。
2. 生产源码、平台测试、插件结构与每次提交的最低 Plugin Verifier 都以该 SDK 为事实源。
3. 定时/手动矩阵验证 IDEA 2025.2.6.2、2025.3.6、2026.1.4、2026.2.0.1；Android Studio 2026.1.2.10 继续验证可选依赖降级。
4. 不设置 `until-build`，但新版本在进入矩阵前不形成兼容承诺。
5. 旧版 `@NotNull` 不支持 TYPE_USE 的位置统一改为声明注解；2025.2 报告的实验性 `ReadAction.computeCancellable` 改为稳定 `ReadAction.compute`，内部算法继续显式检查取消。
6. 依赖锁以最低 SDK 重建；改变编译 SDK 必须显式更新 `platformVersion`、锁文件、兼容矩阵、文档并跑完整门。

## 后果

- 单一插件二进制可以用最低 API 面向四个稳定大版本验证，减少按 IDE 分支发布的维护成本。
- 不能直接使用 2026.1/2026.2 新增 API；确有必要时必须使用公共能力探测或独立兼容适配，并在最低 SDK 编译通过。
- 2025.2 SDK 下载、测试和锁文件体积增加，但这是发布可复现性和真实向后兼容的必要成本。
- Plugin Verifier 仍不是交互证明；四版本和三系统的真实安装、索引、编辑、生成与卸载继续作为 S13 独立阻断门。
