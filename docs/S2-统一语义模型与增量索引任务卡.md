# S2 统一语义模型与增量索引任务卡

> 阶段：S2 MyBatis 统一语义模型与增量索引
> 日期：2026-08-11
> 状态：已验收

## 目标

在不遍历项目文件、不依赖文件名猜测的前提下，把 Mapper、XML 声明、Java/Kotlin 类型、配置来源和模块可见性收敛为可取消、可增量失效的统一查询模型，为 S3～S7 的引用、检查、重构、动态 SQL 和数据库语义提供稳定底座。

## 固定边界

- 只接受精确全限定名、显式注解、显式扫描包、配置项或已解析继承关系，不用简单类名和 `*Mapper` 文件名猜测；
- XML 索引只读取 `FileContent`，不在索引器中创建 PSI、解析项目类或访问外部实体；
- 所有查询使用项目或模块作用域，跨模块结果必须满足依赖可见性；
- 重复 namespace、重复 id 和一个接口多个 XML 保留全部候选，不静默选择第一个；
- 不完整 XML、Dumb Mode、索引竞态、项目关闭和失效 PSI 返回类型化降级结果或空集合，取消异常必须传播；
- Java、XML、配置、项目根和 Dumb 状态分别建立失效依赖，不使用永久缓存、TTL 或全项目文件扫描。

## 任务与验收

| 编号 | 任务 | 验收标准 |
|---|---|---|
| S2-01 | 统一 XML 符号模型 | namespace、statement、resultMap、sql fragment 使用含类型的稳定键；同 id 不串类 |
| S2-02 | 轻量 XML 索引 | 索引器只做一次线性 NanoXML 扫描；拒绝不完整/非 Mapper XML；不解析内外部实体 |
| S2-03 | 通用定位与候选 | 通过 FileBasedIndex 精确查键，并以 PSI 二次确认；重复声明和多 XML 返回全部候选 |
| S2-04 | Mapper 来源模型 | XML namespace、`@Mapper`、MapperScan、配置和继承来源可追踪；证据不足时不认定 |
| S2-05 | 方法、参数与实体模型 | Java/Kotlin、泛型替换、继承方法、参数名/注解及返回实体形成类型化模型 |
| S2-06 | 配置与 TypeAlias | MyBatis XML、Spring Boot 配置、扫描包、资源目录和 TypeAlias 包可增量查询 |
| S2-07 | 模块作用域 | 仅返回当前模块及其依赖可见目标；无依赖的同名 Mapper/namespace 不串联 |
| S2-08 | 精确失效 | 未保存 Java/XML/配置编辑、文件移动删除、模块根变化和 Dumb→Smart 后结果及时更新 |
| S2-09 | 性能与生命周期 | 10 万级语料完成索引/查询；无全项目遍历；查询可取消；项目关闭和索引重建无异常 |
| S2-10 | 统一质量门 | Maven 语料、平台测试、Checkstyle、覆盖率、结构检查、Plugin Verifier 和真实 IDE 验收全绿 |
