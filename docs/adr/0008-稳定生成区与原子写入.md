# ADR-0008：稳定生成区与原子写入

- 状态：已接受
- 日期：2026-08-12
- 决策范围：S8 数据库代码生成、安全合并、预览与写入
- 关联文档：`docs/S8-数据库代码生成与安全合并任务卡.md`

## 背景

数据库 schema 会持续新增、删除、重命名或改变字段类型。简单整文件覆盖会丢失用户手写代码；只按文本相似度或成员名合并又会在重名、格式变化和不完整文件中静默选错。批量生成还会同时创建目录和多个 Java/XML 文件，任一目标失败都可能留下半成品。

## 决策

### 1. 生成核心不直接写文件

模板引擎只消费不可变配置和自有数据库模型，返回确定性候选产物。数据库适配器负责把用户已选、已加载的表转换成自有模型；核心不引用 Database Tools 类型，也不连接数据库。

### 2. 每个生成区携带稳定 ID 和正文指纹

Java 和 XML 产物被拆成少量语义稳定的生成区。每个开始标识包含稳定 ID 与规范化正文的 SHA-256；结束标识再次声明 ID。只有现有正文仍与声明指纹完全一致时，该区域才允许被新候选替换。

### 3. 区域外全部属于用户

生成区外文本不由插件解释或格式化。schema 变化只替换对应生成区，区域外字段、方法、注解、import、resultMap、SQL 片段、statement、空白和原有换行风格原样保留。标识缺失、损坏、集合变化或指纹不符时停止，不自动“修复”标识。

### 4. 未保存文档是事实源

计划和执行前复核优先读取 IntelliJ `Document`，只有不存在缓存文档时才读取 VFS。这样用户尚未保存的手写内容也参与合并和 TOCTOU 比较，不会被磁盘旧版本覆盖。

### 5. 全量计划先于任何写入

所有表和产物先去重、排序、合并并经 Java/XML PSI 解析，再统一形成 CREATE、UPDATE、UNCHANGED 或 CONFLICT。任一冲突阻断整批生成；用户不能通过取消选择冲突文件绕过一致性门。

### 6. 单个稳定 IDE Command 承载整批写入

执行前在写锁内再次复核项目根、父目录、目标存在性、可写性和当前文本。全部通过后，目录创建、文件创建和全文更新由稳定的 `CommandProcessor` API 组合成一个命名 IDE Command；执行前创建 Local History 系统标签。一次 Undo 必须恢复整批文件，一次 Redo 必须重做整批文件。若某一步写入异常，命令在退出写锁前反向恢复已更新文档、删除本批新建文件和空目录；自动回滚本身失败时，错误必须明确指向生成前 Local History 标签。

## 结果

- 用户手写内容不会因正常 schema 演进被生成器覆盖；
- 用户手改生成区会阻止自动更新，需要人工查看差异和决定迁移；
- 生成标识会出现在源码中，这是安全合并和可审计性的显式成本；
- 全文件候选仍经 PSI 校验，但合并边界由稳定标识决定，不依赖格式化器或不稳定 PSI 文本范围；
- 批量创建不依赖 261 的 Experimental `FutureVirtualFile`，最低 261 Plugin Verifier 不产生实验 API 报告；
- 后续 S9～S12 的批量写工具必须复用全量预览、TOCTOU 复核、单命令 Undo 和冲突零写入原则。
