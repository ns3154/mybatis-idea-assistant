# ADR-0009：确定性方法语法与显式关系生成

- 状态：已接受
- 日期：2026-08-12
- 决策范围：S9 方法名 SQL、Wrapper 与 Join 生成
- 关联文档：`docs/S9-方法名SQL-Wrapper与Join任务卡.md`

## 背景

方法名生成若依赖连续字符串切割，会在字段包含 `And`、`Or`、`By` 或操作符后缀时产生多种解释。Wrapper 框架的相似 API 也存在版本和参数顺序差异；Join 若只按 `xxx_id` 名称猜测，可能生成可执行但业务关系错误的 SQL。这三类错误都不应通过“选择第一个候选”掩盖。

## 决策

### 1. 方法名先解析为唯一 AST

解析器以显式操作、字段词典、比较符、连接符、排序和分页规则枚举有界候选。同一输入只在去重后恰有一个候选时成功；零候选返回位置化诊断，多候选返回歧义。取消信号原样传播，更新和删除没有谓词时拒绝。

### 2. 所有生成器只消费成功 AST

Mapper 签名、参数角色、返回类型、XML、Wrapper 共享同一查询 AST 和字段对象，不各自重新解释方法名。动态条件、集合、范围、Like、分页和 TypeHandler 从同一参数模型生成，避免 Java 与 XML 名称漂移。

### 3. 框架和版本必须显式

Wrapper 生成不扫描类路径。用户明确选择 Plus 或 Flex 并输入版本；生成器按版本门和能力矩阵接受或拒绝。Plus/Flex 的条件布尔参数位置与 Like 左右语义分别实现；不能安全表达的聚合、分页或更新不生成替代代码。

### 4. Join 关系必须有人和元数据双重证据

Database Tools 只提供已经加载的主/外键标志。插件列出“一侧外键、另一侧主键”的候选，用户必须明确选择关系、Join 类型和输出属性。生成器再次校验字段属于对应 schema，并以对象身份防止同值字段跨表冒充。没有证据不开放自由文本 ON 条件。

### 5. 写入继续复用 S8 原子边界

方法签名和 XML statement 使用独立稳定方法区，不改变 S8 schema 生成区集合。手改方法区、同名手写声明、目标缺失或 TOCTOU 变化均产生类型化冲突；执行仍由 S8 的全量预览、Local History、单命令和回滚承载。Wrapper 与 Join 暂为只读预览，不制造新的落盘路径。

## 结果

- 歧义、版本差异和关系不确定性会在生成前暴露，而不是形成错误代码；
- 核心生成器可在无 Database Tools、Plus 或 Flex 运行时依赖的环境中独立测试；
- 显式选择增加了一步交互，但关系和框架决策可审计；
- SQLite RIGHT/FULL 与 MySQL FULL 等不稳定或不支持组合被保守拒绝；
- 后续若增加 Kotlin、TkMapper 或更多数据库，必须新增显式适配器和真实版本语料，不得扩展为类路径猜测。
