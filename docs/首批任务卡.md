## 1. 批次目标

在一个可构建、可安装的 IntelliJ IDEA 插件中，完成以下闭环：

1. 识别 Java Mapper 接口；
2. 读取 Mapper XML 的 `namespace` 和 statement `id`；
3. 按“接口全限定名 + 方法名”建立精确关联；
4. 从 Java Mapper 方法导航到唯一匹配的 XML statement；
5. 用正常、namespace 不匹配、statement 缺失三类语料验证行为；
6. 在索引未就绪或目标不存在时安全降级，不抛异常、不阻塞界面。

本批次只证明语义模型、索引、解析和导航可以形成可靠纵切面，不追求功能数量。

## 2. 用户场景

开发者打开 Java Mapper 接口，把光标放在 `UserMapper.findById` 上执行“转到声明/实现”或点击行标图标。插件应定位到 `UserMapper.xml` 中 `id="findById"` 的 statement。

若 XML 的 `namespace` 与 Mapper 全限定名不一致，或者 namespace 正确但 statement 缺失，本批次的解析层必须返回明确的“无匹配”结果。导航入口不得猜测简单类名或跳到同名但错误的目标。

## 3. 输入与期望输出

### 3.1 正常输入

- Java：接口全限定名为 `io.github.mybatisideaassistant.sample.mapper.UserMapper`；
- Java：方法名为 `findById`；
- XML：`namespace` 与接口全限定名完全相同；
- XML：存在唯一 `id="findById"` 的 statement。

期望输出：返回唯一 XML statement，并把导航目标定位到 statement 的名称或开始标签。

### 3.2 边界输入

- 一个 Mapper XML 内存在多种 statement 标签；
- XML 包含空白、注释和不同标签顺序；
- 同名接口位于不同包；
- 项目处于 Dumb Mode；
- PSI 在异步查询期间失效；
- XML 文件被移动、重命名或内容刚刚修改。

期望输出：只按稳定键精确解析；Dumb Mode 或 PSI 失效时返回空结果或可重试状态，不进行全项目扫描。

### 3.3 失败输入

- `namespace` 不等于 Mapper 全限定名；
- namespace 正确，但不存在与方法同名的 statement；
- 同一个稳定键出现多个候选；
- XML 语法不完整或文件正在编辑。

期望输出：无匹配时不导航；多候选时返回候选集合供用户选择；不完整 XML 只影响当前文件，不得使插件或索引任务失败。

## 4. 任务拆分

### B01-01：工程骨架与质量门

目标：创建能编译、测试、打包和启动沙箱 IDE 的插件工程。

允许修改：根构建配置、插件源码、测试和 CI 配置。
禁止事项：引入尚未使用的可选平台依赖；添加默认联网或遥测；使用未说明的 IntelliJ 内部 API。

必须交付：

- IntelliJ Platform Gradle Plugin 2.x 工程；
- Java 21 工具链；
- 插件描述符和中文名称/说明；
- 单元测试、平台测试、构建插件和 Plugin Verifier 入口；
- 一条命令启动沙箱 IDE。

验收：

```bash
./gradlew clean test buildPlugin
./gradlew verifyPlugin
```

### B01-02：Java Mapper 识别

目标：把 Java Mapper 接口转换成稳定、最小的语义描述。

首批识别规则：

- 仅处理 Java 接口；
- 以接口全限定名作为 Mapper 稳定键；
- 收集当前接口中声明的方法名；
- 不把简单类名相同视为同一个 Mapper；
- 注解 Mapper、继承方法和 Kotlin 接口留到后续任务卡，不在此任务中猜测。

必须测试：普通接口、同名不同包、无全限定名的临时 PSI、文件修改后的缓存失效。

### B01-03：XML namespace 与 statement 索引

目标：从 Mapper XML 建立可增量查询的稳定键。

索引键：

- Mapper 键：`namespace` 原始完整值；
- statement 键：`namespace + "#" + id`；
- statement 标签首批支持 `select`、`insert`、`update`、`delete`。

约束：

- 索引数据只保存可序列化的标量，不保存 `PsiElement`；
- 查询路径不得遍历全部项目文件；
- XML 修改、移动、删除后，旧键必须失效；
- 不完整 XML 应保守返回，不把异常传播到 EDT。

必须测试：四类 statement、重复键、不完整 XML、注释/空白、文件移动和索引重建。

### B01-04：精确解析与导航

目标：从 Mapper 方法解析到 XML statement 并提供导航入口。

解析规则：

```text
Mapper 接口全限定名 + "#" + Java 方法名
                         ↓ 精确匹配
XML namespace           + "#" + statement id
```

约束：

- 零个目标：返回空结果；
- 一个目标：直接导航；
- 多个目标：保留全部候选，不静默选择第一个；
- 跨异步边界使用稳定键或 `SmartPsiElementPointer`；
- ReadAction、Dumb Mode、取消和 EDT 边界必须有明确处理。

必须测试：成功跳转、namespace 不匹配、statement 缺失、多候选、Dumb Mode 和 PSI 失效。

### B01-05：样例语料与回归

目标：以 `samples/java-mybatis-minimal` 作为首个真实语料库。

必须覆盖：

- 可实际执行的 Java Mapper 与 XML 正常关联；
- namespace 不匹配的失败语料；
- Mapper 方法缺少同名 statement 的失败语料；
- 失败语料可以被 IDE 测试读取，但不破坏样例 Maven 构建。

验收：

```bash
mvn -f samples/java-mybatis-minimal/pom.xml clean verify
```

### B01-06：真实 IDE 验收

目标：在目标 IDE 验证自动化测试覆盖不到的安装、索引和交互路径。

人工步骤：

1. 启动沙箱 IDEA，并打开 `samples/java-mybatis-minimal`；
2. 等待 Maven 导入和索引完成；
3. 从 `UserMapper.findById` 导航到 `UserMapper.xml` 的 `findById`；
4. 打开两份失败语料，确认解析结果分别为 namespace 不匹配和 statement 缺失；
5. 修改 statement `id`，确认旧关联消失；撤销修改，确认关联恢复；
6. 检查 IDE 日志，无新增未捕获异常、索引风暴或 EDT 卡顿。
