# 首批功能矩阵

> 矩阵版本：0.1
> 范围：Mapper 方法到 XML statement 的最小纵切面
> 语义原则：首批只做精确匹配；不以猜测换取“看起来能跳转”

## 1. 状态与优先级说明

- `P0`：首批纵切面不可缺少，错误会使核心结果不可信；
- `P1`：首批体验或稳定性的重要保障；
- `P2`：后续增强，不阻断首批交付；
- `语料就绪`：已有可供实现和测试使用的输入；
- `待实现`：行为已确定，尚未交付代码；
- `后续`：明确不进入 B01。

## 3. 首批精确语义

### 3.1 Mapper 键

```text
mapperKey = Java 接口全限定名
xmlMapperKey = XML mapper/@namespace 的完整字符串
```

仅当两个字符串完全相等时，Mapper 与 XML 才关联。首批不解析 type alias，不根据 XML 文件名推断 namespace，也不做简单类名兜底。

### 3.2 Statement 键

```text
methodKey = Java 接口全限定名 + "#" + Java 方法名
statementKey = XML namespace + "#" + statement/@id
```

首批不解决 Java 重载。一个方法名对应多个重载时，解析层仍会得到同一个 statement 候选；上层必须把它标记为多方法共享结果，不声称参数签名已经被 MyBatis 精确区分。

### 3.3 结果类型

解析层至少区分以下结果，避免上层依赖异常文本：

| 结果 | 含义 | 导航行为 |
|---|---|---|
| `唯一匹配` | 稳定键恰有一个有效目标 | 直接导航 |
| `无 Mapper XML` | namespace 无匹配 XML | 不导航 |
| `statement 缺失` | namespace 已匹配，方法名无 statement | 不导航 |
| `多候选` | 稳定键有多个有效目标 | 展示候选 |
| `索引未就绪` | Dumb Mode 或索引不可查询 | 静默降级并允许稍后重试 |
| `源已失效` | 查询期间 PSI 或项目生命周期失效 | 取消当前动作 |

## 5. 后续扩展登记

以下项目不改变首批的精确语义，在独立任务卡中扩展：

- Java 重载、继承 Mapper、泛型方法和桥接方法；
- `@Mapper`、`@MapperScan` 与框架基类识别；
- 一个接口多个 XML、跨模块资源和依赖可见性；
- XML 到 Java 反向导航；
- 缺失、重复和 namespace 错误的 Inspection/Quick Fix；
- Kotlin K2、注解 SQL、MyBatis-Plus 和 MyBatis-Flex。
