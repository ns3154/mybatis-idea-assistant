# ADR-0011：本地 MCP 与设置安全边界

## 状态

已接受，随 S12 实施。

## 背景

插件需要向本机自动化客户端提供 Mapper、statement、参数、数据库元数据和安全生成能力。MCP 会把原本只在 IDE 内触发的能力暴露到本地端口，因此认证、浏览器跨域、项目选择、写入授权和生命周期都成为新的高影响边界。

## 决策

1. 使用项目级 MCP 服务；全局设置只决定是否允许创建服务，每个已打开项目获得独立随机 token、会话和端口。
2. 监听地址固定为 IPv4 回环 `127.0.0.1`。默认端口为 `0`，让操作系统分配空闲端口；用户配置固定端口时只接受 1024～65535。
3. token 使用 `SecureRandom` 生成至少 256 bit 熵，只存在内存；不写 PasswordSafe，因为每次启动轮换比长期凭据更小权。
4. HTTP 请求拒绝非 POST、非回环来源、非本地 Host、任何浏览器 Origin、错误 Bearer token、超限 body 和未知 MCP 会话。
5. MCP 协议层只实现有界 JSON-RPC 请求；通知返回 202，调用返回单个 JSON。服务不提供任意文件、SQL 或反射执行入口。
6. 工具注册表是唯一白名单事实源；设置中的工具 ID 只能缩小暴露范围，不能注册新工具。写工具还需独立的总开关。
7. 写入采用 preview/confirm 两阶段。preview 不改文件并返回短期、一次性、绑定项目与源版本的令牌；confirm 再次验证源、目标、冲突和授权，然后复用现有 IDE Command/Undo 实现。
8. 设置 schema 显式版本化；导入整体校验后原子替换。导出排除密码、token、会话、项目路径和数据库凭据。
9. 项目关闭、插件禁用、设置关闭或启动失败时必须同步停止 listener、清除会话/预览并关闭执行器；关闭失败视为发布阻断。

## 后果

- 用户必须在每次 IDE 启动后重新取得 endpoint/token，减少凭据长期泄漏风险；
- 多项目不会共享权限或工具上下文，但会使用不同本地端口；
- 写工具实现成本高于直接执行，但能维持既有预览、TOCTOU、Undo 和失败恢复承诺；
- 只读工具仍需服从 Dumb Mode、取消、模块作用域和元数据加载状态，不能把“不确定”伪装为确定结果。
