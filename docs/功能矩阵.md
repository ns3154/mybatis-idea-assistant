## 3. 首批精确语义

### 3.1 Mapper 键

```text
mapperKey = Java 接口全限定名
xmlMapperKey = XML mapper/@namespace 的完整字符串
```

仅当两个字符串完全相等时，Mapper 与 XML 才关联。首批不解析 type alias，不根据 XML 文件名推断 namespace，也不做简单类名兜底。

### 3.2 Statement 键

```text
methodKey = Java 接口全限定名 + "#" + Java 方法名
statementIndexKey = "STATEMENT" + NUL + XML namespace + NUL + statement/@id
```

`NUL` 是内部不可出现在用户段值中的分隔符；符号类型避免 statement、resultMap 和 SQL fragment 同名时串类。首批不做参数级 Java 重载消歧。正向 Java → XML 遇到重载时返回“不支持的源”且不显示 gutter，避免把单个重载误称为唯一映射；反向 XML → Java 遇到重载时保留全部同名方法，由平台展示候选。

### 3.3 B02 结果类型

以下类型是 B02 已实现并通过统一质量门的稳定语义：

解析层至少区分以下结果，避免上层依赖异常文本：

| 结果 | 含义 | 导航行为 |
|---|---|---|
| `唯一匹配` | 稳定键恰有一个有效目标 | 直接导航 |
| `无 Mapper XML` | namespace 无匹配 XML | 不导航 |
| `statement 缺失` | namespace 已匹配，方法名无 statement | 不导航 |
| `多候选` | 稳定键有多个有效目标 | 展示候选 |
| `索引未就绪` | Dumb Mode 或索引不可查询 | 静默降级并允许稍后重试 |
| `源已失效` | 查询期间 PSI 或项目生命周期失效 | 取消当前动作 |
| `不支持的源` | 调用方传入非本批支持的 Java 源 | 不导航，不尝试猜测 |

namespace、statement、resultMap 与 SQL fragment 写入新的统一 `FileBasedIndex`：`mybatis.idea.assistant.xml.symbol`。新索引 ID 使旧 B02 缓存自然重建；零个 statement 候选时，解析层仍能区分“没有对应 Mapper XML”和“Mapper XML 存在但 statement 缺失”。

## 6. B03 反向导航语义

```text
mapper/@namespace 完整值 ──精确 FQN──> Java 接口
statement/@id          ──精确方法名──> 当前接口声明的方法候选
```

- 只接受全限定名完全相等的接口，不按 XML 文件名或简单类名兜底；
- 一个同名方法时直接导航；Java 重载产生多个候选时全部保留并交由平台展示；
- 不把继承方法、参数签名推断或框架基类扩展混入 B03；
- Dumb Mode、无精确接口、源失效或 XML 结构不支持时不导航。

## 7. B04 缺失 statement 检查语义

B04 只消费 B02 的类型化解析结果；只有 `statement 缺失` 会注册编辑器问题。检查目标进一步收窄为 Java 接口直接声明的、没有重载的抽象实例方法，并排除默认方法、静态方法、MyBatis `Select/Insert/Update/Delete` 与对应 Provider 注解覆盖的方法，以及不需要 XML statement 的 `@Flush` 方法。

以下结果均保守静默：

- 没有对应 namespace 的 Mapper XML；
- 已有唯一 statement 或存在重复候选；
- 普通类、注解类型、重载方法及非抽象方法；
- 索引未就绪、源已失效或用户取消检查。

警告只标记 Java 方法名。B04 自身不推断 CRUD 标签、不提供 Quick Fix，也不创建或修改 XML；S3 在保持相同告警边界的前提下新增显式 Quick Fix，由用户选择 `select/insert/update/delete` 与精确目标 XML，执行前再次校验冲突和写权限。B04 批次的 63 个平台测试、Maven 样例回归、最低 2026.1 GA Plugin Verifier 和副屏幕真实 IDE 交互验收均已通过，F-016 据此标记“已验收”。
