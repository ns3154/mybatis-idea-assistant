# ADR-0003：精确引用与安全写入

- 状态：已接受
- 日期：2026-08-11
- 决策范围：S3 引用、导航、基础 Inspection 与 ModCommand Quick Fix
- 关联文档：`docs/S3-精确引用基础检查与安全修复任务卡.md`、`docs/S3-精确引用基础检查与安全修复验收记录.md`

## 1. 背景

S2 已建立可增量失效、带模块作用域的 Mapper/XML/配置语义底座，但编辑器仍需要把这些符号暴露为 IntelliJ 原生引用、查找使用、行标、检查和可撤销修复。如果各入口各自扫描文件或猜测目标，会重新引入多事实源、跨模块串联和错误写入。

## 2. 决策

### 2.1 引用只消费统一符号与精确 Java PSI

- XML `namespace` 只引用全限定名完全相等的 Java 接口；
- statement `id` 只引用当前 namespace 接口中同名方法，重载全部返回；
- `refid` 只引用当前/显式 namespace 的 SQL fragment；`resultMap` 与 `extends` 只引用 ResultMap；
- 逗号分隔的 `resultMap` 值按各自文本范围建立独立引用；
- 注解 SQL 和 Provider 通过公开 Java PSI API 解析类、方法与属性，不复制框架实现；
- Find Usages 复用相同引用定义，不另建文本搜索语义。

所有结果使用调用元素的 resolve scope，并在返回前复核 PSI、项目生命周期和取消状态。

### 2.2 多目标是合法结果

一个 Mapper 对应多个 XML、重复 statement、Java 重载和 Provider 重载都可能产生多个候选。解析层保留全部有效候选，导航层交给平台展示；顺序只用于稳定 UI，不改变正确性。

### 2.3 Inspection 按误报风险分级

默认启用：

- 已确认 Mapper 且确无 XML；
- 已有精确 Mapper XML 但缺少 statement；
- 相同 namespace、id 与 databaseId 下的重复 statement。

默认关闭：

- namespace 无 Java 接口，因为 MyBatis 允许非绑定 namespace；
- statement 无 Mapper 方法，因为可能由字符串、框架或动态方式调用；
- 多参数缺少 `@Param`，因为 MyBatis 仍可使用 `param1`、`arg0` 或实际参数名。

默认关闭不代表无实现：这些检查仍需真实注册、正反例、说明文档和生命周期测试。

### 2.4 所有写入使用 ModCommand

创建 Mapper XML、创建 statement 和添加 `@Param` 统一满足：

1. 提供 IntelliJ intention preview；
2. 在单个 ModCommand 中完成，单次 Undo 可完全恢复；
3. 通过智能指针定位目标，执行前重新校验 namespace、方法和写权限；
4. 只使用现有生产资源根，目标 XML 用项目相对路径区分；
5. 发现文件、statement 或注解冲突时停止，不覆盖、不合并猜测；
6. 不在 ModCommand 外做二次写入或格式化命令。

未使用 statement 只提供定位接口。删除无法静态证明安全，因此不进入 S3。

## 3. 被否决的方案

### 3.1 文本搜索实现引用

会把注释、其他 namespace、不可见模块和同名不同类型符号混入结果，也无法可靠支持重命名与查找使用。

### 3.2 多候选时选第一个

索引顺序不是业务语义；选择第一个会让结果随缓存、文件顺序和并发时机变化。

### 3.3 默认启用所有 Inspection

MyBatis 允许动态调用、非绑定 namespace 和隐式参数名。无法证明错误的提示会降低用户对检查结果的信任。

### 3.4 直接修改 PSI 后补一个 Undo

分散的写命令无法稳定提供预览、原子性和失败恢复。S3 使用 ModCommand 把预览、执行和撤销绑定到同一操作模型。

### 3.5 为“未使用”提供自动删除

静态引用不完整时，删除可能破坏运行时字符串调用、框架约定或动态加载；S3 只定位精确接口。

## 4. 结果与代价

正面结果：

- XML/Java 关系成为平台原生引用，可用于导航和查找使用；
- 多模块、重复声明和重载行为保持确定、可解释；
- 低风险检查默认可用，高风险检查仍可由用户显式开启；
- 首组写入能力具备预览、原子 Undo、冲突停止和目标可辨识性。

需要接受的代价：

- Provider 的完全动态返回值无法静态求值，只导航到可解析类/方法；
- 未使用 statement 不能被证明为绝对未使用；
- S3 不处理参数表达式、复杂 ResultMap 属性、OGNL、SQL 或数据库元数据；
- 每次 IntelliJ 大版本升级都必须复跑引用注册、ModCommand 与待移除 API 检查。

## 5. 验证方式

必须同时通过平台测试、Checkstyle、JaCoCo、项目配置、插件结构、最低 IDEA 2026.1 GA Plugin Verifier、两套 Maven 语料、20/20 生命周期、5/5 可选依赖隔离，以及副屏真实 IDEA 的 Java/XML/refid 导航与告警动作可见性验收。

## 6. 重新评审触发条件

- 引用开始使用文件名、简单类名或全项目文本搜索兜底；
- 任何多候选入口静默选择一个目标；
- 默认检查开始报告无法证明的动态语义问题；
- 写操作绕过 ModCommand、缺少预览/Undo，或可覆盖未知用户内容；
- 新增删除、批量重构或跨文件生成能力；
- S4 需要改变参数、ResultMap 或 TypeAlias 的引用稳定键。
