# ADR-0005：符号化动态 SQL 与字符级源映射

- 状态：已采纳
- 日期：2026-08-11
- 决策范围：S5 动态 SQL 中间表示、分支模型、include 与源位置映射
- 关联文档：`docs/S5-动态SQL编译器与源位置映射任务卡.md`

## 背景

动态 MyBatis XML 不是一个可通过删除标签得到的静态 SQL 字符串。`if`、`choose`、`trim` 和 `foreach` 会改变 token、分隔符与前后缀；`include` 可以跨文件并做 property 替换；CDATA 和 XML entity 又使虚拟 SQL 字符与 XML 源字符长度不同。

若提前穷举分支，节点数会随嵌套条件指数增长。若只保存拼接后的字符串，S7 的 SQL 错误、补全和重构无法准确返回 XML。若 source map 保存 PSI，未保存编辑和重解析后会产生失效引用。

## 决策

### 1. 使用不可变符号化树，不枚举分支组合

中间表示采用有序不可变节点：文本、序列、条件、选择、Trim、ForEach、Bind、Include 和诊断。条件节点保存表达式文本与来源范围，S5 不求值。choose 保存有序 when 与可选 otherwise，运行期短路语义由节点表达。

任何编译步骤的空间复杂度必须与 XML 节点数和文本长度近似线性；禁止生成分支笛卡尔积。

### 2. source map 使用稳定文件标识和压缩映射段

映射段只保存：

- 虚拟 SQL 半开区间；
- 稳定源文件 URL 与源半开区间；
- `EXACT`、`DECODED`、`SYNTHETIC` 三类映射语义。

普通等长文本可合并为 `EXACT` 段；XML entity 使用 `DECODED` 段，一个虚拟字符可对应多个源字符；生成的前后缀和分隔符使用 `SYNTHETIC`，并关联最近的标签或属性来源但不声称字符等价。映射对象不持有 PSI。

### 3. 编译器消费 XML PSI，核心模型保持平台无关

平台编译层负责从有效 XML PSI 提取文本、标签、属性和稳定文件 URL；IR、范围校验、映射查询和条件模型使用纯 Java 类型。这样纯模型可做大量黄金/随机测试，平台测试只验证 PSI 提取、索引、生命周期和 UI 集成。

### 4. include 使用现有统一符号索引

静态 `refid` 通过 `MyBatisXmlSymbolLocator` 按 SQL fragment 类型、精确 namespace 和调用元素 resolve scope 查询。只有唯一目标才展开。展开栈使用稳定文件 URL、namespace、id 和偏移构成键，检测跨文件循环。

include property 形成嵌套替换环境；替换来源同时记录调用属性和 fragment 原文，供以后诊断与重构显示。动态 refid、重复目标或无法确定 property 不猜测。

### 5. 作用域只建模，不在 S5 实现 OGNL

ForEach 和 Bind 节点声明名称、表达式与词法范围；参数/集合元素的基础类型可复用 S4 参数模型。完整表达式 PSI、类型推导、引用和检查属于 S6。

## 后果

### 正面

- 动态分支不会指数展开；
- SQL 错误、补全和重构可以统一消费同一 source map；
- 跨文件 include、entity 和合成文本的位置语义明确；
- 核心算法可脱离 IDE 做随机和不变量测试。

### 代价

- 下游 SQL 解析器必须理解符号化节点或显式选择一个保守渲染策略；
- Trim/ForEach 的准确运行期文本需要表达式值，S5 只能保留结构；
- 一个虚拟范围可能对应多个文件和不连续源范围，调用方不能假设单一 TextRange。

## 重新评估条件

出现以下任一情况时重新评估：

- S7 的 SQL PSI 无法消费符号化树，需要新的 guarded-token 适配层；
- MyBatis 新版本改变 Trim、ForEach 或 include property 语义；
- 1000 节点/百万字符夹具超过 S5 预算，映射段需要更紧凑的数据结构；
- IntelliJ 提供稳定的跨语言多源映射公共 API，能够替代自有映射模型。
