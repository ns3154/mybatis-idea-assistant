# S0 产品基线与语料任务卡

> 批次：S0
> 状态：已完成
> 目标：为完整交付范围建立无未决核心语义的行为矩阵和可构建语料，作为 S1～S13 的共同测试输入。

## 1. 用户场景

插件开发者在实现导航、参数、动态 SQL、OGNL、数据库或生成能力前，必须能从仓库内找到对应的真实输入、成功预期和保守失败预期，并能用一条命令证明语料本身可编译、可解析。

## 2. 输入与输出

输入：

- Java Mapper、继承、泛型、单/多参数、`@Param`、集合、Map 和注解 SQL；
- 跨模块 Spring Boot 配置、`@MapperScan`、TypeAlias 和 Mapper XML；
- ResultMap、association、collection、constructor、discriminator、columnPrefix；
- include、bind、foreach、choose、trim、where、set；
- Kotlin K2 Mapper、数据类、可空/默认参数和 XML；
- MyBatis-Plus、MyBatis-Flex、TkMapper 真实依赖；
- MySQL、PostgreSQL、Oracle、SQL Server、SQLite、达梦方言夹具；
- 完整 P0 能力的正常与失败行为清单。

输出：

- `docs/交付功能行为矩阵.md`；
- `samples/semantic-corpus` 五模块 Maven 工程；
- 机器校验的 P0 正反例清单；
- 命令行和 IDEA 2026.1 导入证据。

## 3. 正常、边界、失败和取消

- 正常：五模块实际编译；Spring/Java/Kotlin XML 可由 MyBatis 解析；三种框架基类可加载；六方言文件具备差异标识。
- 边界：Kotlin 模块必须实际产生 class 并执行测试，禁止“无源码可编译”的空绿。
- 失败：namespace 不匹配、include 循环等失败语料必须隔离在测试资源，不进入应用资源。
- 取消：Maven/IDE 导入允许用户取消；取消不得改写源码或生成受 Git 跟踪的本机配置。

## 4. 修改边界

允许修改：`samples/semantic-corpus/**`、S0 文档、README、CI 和 Dependabot 入口。

禁止修改：插件生产语义、B01～B04 已验收行为和用户其他项目。

## 5. 性能、线程和写入要求

- S0 不引入插件运行期线程或项目扫描。
- 样例构建不启动数据库、网络服务或后台常驻进程。
- IDE 导入只产生被 `.gitignore` 覆盖的 `.idea` 和构建目录。
- 所有失败语料只读，不由生产配置加载。

## 6. 自动化门禁

```bash
mvn --batch-mode --file samples/java-mybatis-minimal/pom.xml clean verify
mvn --batch-mode --file samples/semantic-corpus/pom.xml clean verify
```

语义语料契约必须证明：

- Spring 跨模块 XML 解析通过；
- Kotlin K2 源码和测试确实执行；
- Plus/Flex/TkMapper 类型可解析；
- 六种方言夹具存在并包含各自标识；
- 每个 P0 编号同时具备 `NORMAL` 和 `FAILURE` 行为语料。

## 7. 副屏 IDEA 验收

1. 只在副屏打开 `samples/semantic-corpus`；
2. 信任当前本地工程，不信任整个 `samples` 目录；
3. 等待 Maven 导入和项目分析完成；
4. 确认五个模块均被识别，Java/Kotlin/XML 无项目级错误；
5. 从 Maven 工具窗口运行 `verify` 或用已通过的命令行构建结果对照；
6. 检查项目目录仅产生被忽略的 `.idea`/`target`，没有源码改写；
7. 记录异常、未决警告和屏幕位置。

## 8. 退出条件

- 完整行为矩阵不存在“以后再确定”的核心语义；
- 全部 P0 有正常/失败行为语料；
- 两个 Maven 样例工程命令行构建通过；
- 语义语料在 IDEA 2026.1 正确导入和索引；
- 独立实现和许可证边界有文档；
- 无已知 P0/P1。
